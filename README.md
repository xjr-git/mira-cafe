# 雨夜咖啡馆 · Mira — 实时互动场景 MVP

不是聊天消息列表，而是一个**场景**：暴雨夜的咖啡馆里，旅拍摄影师 Mira 正在等人。你可以用文字或按住麦克风和她交流；她会说话、变表情、做动作，剧情推进时改变整个场景，并从她的相机里"掏出"动态生成的拍立得照片。

> 72 小时实验题交付 · 移动端网页优先 · 无 API Key 也能完整体验（Mock 模式）

---

## 快速启动

```bash
# Windows: 双击 start.bat（自动建 venv、装依赖、起服务、开浏览器）
# Linux / macOS:
./run.sh
# 或者 Docker:
docker compose up
```

打开 **http://127.0.0.1:8000/** 即可。

- **Mock 模式（默认，无需任何密钥）**：剧本引擎驱动剧情，EdgeTTS 语音，预置拍立得照片，全链路可体验。
- **完整模式**：复制 `.env.example` 为 `.env`，填入 `DASHSCOPE_API_KEY`，重启后自动启用 qwen-plus（LLM）+ CosyVoice2（TTS）+ wanx2.1（拍立得生图）。

## 演示要点（对应录屏脚本）

1. 文字互动：情绪/动作/场景随对话变化（试试问"你在等谁""你是谁""下雨"）
2. 语音互动：按住 🎤 说话，Mira 语音回复 + 同步字幕
3. **打断**：她说话时按住 🎤（或点 ⏹ 打断）——语音立即停、未播内容全部失效、切倾听态
4. 迟到响应防护：连续快速打断，已失效回复永远不会"诈尸"重播
5. 多模态：聊到"照片/摄影/相机"→ 拍立得显影动画 → 雨停后整个场景切换
6. 失败降级：断网可见错误提示与降级；LLM 超时自动回落剧本模式

## 系统结构

```
浏览器（零构建 vanilla ES modules）
  场景层(背景/雨/拍立得)  角色(SVG分层: 5表情/3动作/眨眼呼吸/口型)  UI(字幕/输入/PTT)
        ▲  SSE 事件流（round/state/subtitle/audio/directive/done，全部带 round_id）
FastAPI 单服务
  Session(剧情节点)  RoundGuard(轮次/打断/指标)  指令协议校验
  providers/: llm(剧本↔qwen-plus)  tts(edge-tts↔CosyVoice2)  image(预置↔wanx2.1)
```

模块：`backend/app/main.py`（接口与 SSE 编排）、`story.py`（剧本引擎+剧情节点图）、`guard.py`（打断安全）、`directives.py`（指令白名单校验）、`providers/*`（可替换 Provider）、`static/`（前端）。

## 语音交互与打断流程

选型：**STT(浏览器 Web Speech) → LLM(qwen-plus/剧本) → TTS(CosyVoice2/EdgeTTS) 组合方案**，未用端到端实时语音模型——为了把场景指令注入和打断时序的控制权留在自己手里（取舍详见下节）。

交互方式：**按住说话（PTT）为主 + 显式打断按钮**。选 PTT 而非纯自动 VAD 的原因：
1. 笔记本/手机外放时回声消除不可靠，自动 VAD 会把 Mira 自己的声音当成人声（题目"扩展"里提到的回声问题）；
2. PTT 的"按下"语义天然等于"打断 + 开始听"，状态切换干脆，附和词（"嗯""对"）不会误触发；
3. Web Speech API 浏览器端实现，移动端无需额外采集链路。

打断时序（本轮对话分配递增 `round_id`，所有事件携带）：

```
用户按住 PTT
 ├─ 前端: abort() 在途 SSE 请求 → 服务端 SSE 生成器被取消，未合成的句子不再合成
 ├─ 前端: 立即 stop 当前音频、清空待播队列、UI 切"倾听"
 ├─ 前端: barredRound = latestRound —— 之后所有 round_id ≤ 该值的事件一律丢弃
 └─ 后端: /api/interrupt 把 ≤ 该轮的所有轮次标记为 dead；迟到分片不再下发
```

双重过滤（前端 round_id 检查 + 后端 dead 标记）保证：**上一轮迟到的网络响应既不会覆盖画面，也不会重新开始播放**；尚未播放的字幕、动作、媒体事件随本轮一并失效。

## 角色与场景指令协议

LLM（或剧本引擎）输出 JSON，`say` 送 TTS，`directives` 经**白名单校验**后转为 SSE 事件——幻觉指令不可能进入场景：

```json
{
  "say": "你看这张——京都的雨夜，灯笼全泡在水里。",
  "directives": [
    {"t": "emotion", "v": "happy"},          // neutral/happy/shy/sad/surprised（5 种）
    {"t": "action",  "v": "look_camera"},    // stir_coffee / look_camera / gaze_window（3 种）
    {"t": "scene",   "v": "rain_stop"},      // 背景切换 + 雨停（全剧一次）
    {"t": "media",   "kind": "polaroid", "prompt": "...", "job_id": "..."},
    {"t": "goto",    "v": "reveal"}          // 剧情节点: opening→smalltalk→confide→reveal→ending
  ]
}
```

前端按 round 分桶消费，打断时整桶作废；拍立得通过 `/api/image` 任务化：**生成中=显影动画剧情化等待**（不冷场），成功后渐显，失败自动降级为预置旧照片；prompt 哈希缓存复用。

## 多模态能力选择

选「**根据当前对话动态生成的场景图片**」（wanx2.1-t2i）：剧情锚点是 Mira 的摄影师身份——聊到摄影时她"给你看一张拍立得"。照片内容是风景而非人物，规避了生成式角色外观一致性难题；照片是"她拍的照片"，视觉事件与当前对话/剧情节点强绑定，不是固定计时器。

## 模型与第三方服务

| 能力 | 完整模式 | Mock / 降级 |
|---|---|---|
| LLM | 阿里 DashScope qwen-plus（JSON mode） | 内置剧本引擎（也作 LLM 超时兜底） |
| TTS | DashScope CosyVoice2（longxiaochun） | edge-tts（免费无 Key，默认） |
| STT | 浏览器 Web Speech API（Chrome/Edge） | 文字输入 |
| 生图 | DashScope wanx2.1-t2i-turbo | 预置 3 张 AI 生成拍立得 |

素材来源：背景与拍立得为 AI 生成（生成式模型），角色为手工分层 SVG；未使用带版权限制的 Live2D 素材。

## 关键技术选择与取舍

- **组合语音方案而非端到端实时模型**：端到端延迟更低，但指令协议注入、打断时序、Mock 回放全部变成黑盒；组合方案首包 ~1s，用"字幕先行 + 逐句 TTS"弥补，且每一段都可被替换（Provider 抽象）。
- **PTT 而非自动 VAD**：理由见上节；自动 VAD 留作两周演进项（需 AEC）。
- **零构建前端（vanilla ES modules）而非 Vite/React**：本题重交互编排而非 UI 复杂度，零构建换来"一条命令启动、无 node 依赖、单服务托管"，降低评审启动成本。
- **TTS 逐句合成 + 磁盘哈希缓存**：首句音频先出，打断时未合成部分自然终止；缓存让重复台词零延迟。
- **Live2D → 分层 SVG**：Live2D 免费模型有授权限制且口型/动作调试耗时不可控；分层 SVG 在 72h 内能做到 5 表情/3 动作/眨眼/呼吸/口型全覆盖且完全可控。

## 已知问题

- 自动语音活动检测（自动打断）未做：当前为 PTT + 按钮打断（原因见取舍）；下一步需回声消除后再开。
- 浏览器 Web Speech API 依赖 Chrome/Edge 及其联网识别服务，Safari/Firefox 上麦克风按钮自动隐藏并提示。
- 单全局会话（题目明确不需要账号系统）；`POST /api/reset` 重置剧情。
- 服务端 TTS 为逐句整段合成（非 token 级流式），长句首包延迟略高，已用短句切分缓解。
- 非HTTPS 环境下部分浏览器限制麦克风（`localhost` 不受限）；公网部署需配置 TLS。

## 如果继续开发两周

1. **自动打断 + 回声消除**：WebRTC AEC 采集链路 + 能量 VAD + 附和词分类（"嗯/对"不触发打断），把 PTT 变为可开关的自动模式；
2. **真流式 TTS**（CosyVoice2 WebSocket 流式 + 音频分片打时间戳），字幕与音频时间线精确对齐，口型随音频振幅驱动；
3. **视频演出层**：关键剧情节点播放预加载的 MP4 片段（无黑屏切换、失败降级为静态画面），与常驻角色衔接；
4. **会话回放/诊断**：把每轮事件流（含音视频 URL）落盘为可回放 JSON，配合 `/metrics` 做问题定位；
5. **Provider 多云抽象**：LLM/TTS/生图统一接口 + 配置热切换 + 用量观测页。
