## 3. 语音打断（6 条逐一）

| 题目要求 | 状态 | 证据 |
|---|---|---|
| 角色说话时用户能开始新语音输入并打断 | ✅ | 按住🎤即打断（voice.js 的 PTT 语义自带打断） |
| 当前角色语音立即停止 | ✅ | `stopPlayback()` 立即 pause 当前音频并清队列 |
| 尚未完成的回复被取消或失效 | ✅ | 前端 abort SSE；服务端该轮标记 dead，TTS 任务在 finally 中 cancel（`main.py` chat.gen finally） |
| 未播放的字幕/动作/媒体事件不继续出现 | ✅ | 前端 `barredRound` 水位线：一切 `round_id ≤ 水位线` 的事件直接丢弃 |
| 页面切换到倾听状态并处理新输入 | ✅ | interrupt() 置 listening，新输入直接发起下一轮 |
| 上一轮迟到的网络响应不覆盖当前状态或重新开始播放 | ✅ 实测 | 打断风暴测试：打断后立即开新轮，旧轮零脏事件泄漏（`concurrency_test.py` Test C） |
| README 说明选择该方式（VAD vs PTT）的原因 | ✅ | README「技术取舍」：按住说话语义明确、无误触发，代价是少了随口插话的自然感 |
